# 페이스북 게시물 책자 만들기

페이스북에서 내려받은 내 데이터를 **읽고 · 고르고 · 고쳐 써서**, 인쇄해 제본할 수 있는
**PDF 책자**로 만들어 주는 웹앱입니다.

파일은 어디로도 전송되지 않습니다. ZIP 해제, 사진 추출, 조판, PDF 저장까지
**전부 브라우저 안에서** 이루어집니다. 서버도, 외부 라이브러리도, 추적도 없습니다.

👉 **[바로 사용하기](https://koreanha.github.io/facebook/)** (GitHub Pages)

---

## 쓰는 순서

### 1. 페이스북에서 데이터 내려받기

1. 페이스북 → **설정 및 개인정보** → **설정** → **내 정보에 액세스** → **정보 다운로드**
   (모바일 앱은 *설정 → 개인정보 센터 → 내 정보 다운로드*)
2. 범위는 **Facebook의 내 활동 → 게시물(Posts)** 만 고르면 용량이 작아 빨리 준비됩니다.
3. 형식은 **JSON**을 고르세요. (HTML도 읽지만 JSON이 훨씬 정확합니다.)
4. 미디어 화질은 **중간~높음**이면 인쇄 품질이 넉넉합니다.
5. 준비되면 알림이 옵니다. 받은 **ZIP 파일을 압축 풀지 말고 그대로** 올리세요.

### 2. 글 고르고 다듬기

- 날짜·검색어·글자 수·사진 유무로 걸러 내고, 체크를 풀어 뺄 글을 고릅니다.
- 본문은 그 자리에서 고쳐 쓸 수 있습니다. **원문은 따로 보존**되어 언제든 되돌릴 수 있습니다.
- 편집 내용은 브라우저에 자동 저장되고, `편집본 저장`으로 JSON 파일로 백업할 수도 있습니다.

### 3. 책 디자인

판형(A4·B5·A5·Letter·정사각), 여백과 제본 여백, 단 수, 글꼴과 크기, 줄 간격,
연도/연월별 장 나누기, 목차, 머리말, 쪽 번호, 사진 크기와 장수 — 바꾸는 즉시 미리보기에 반영됩니다.

**글 배치**는 세 가지입니다.

- **글 하나를 한 페이지에** (기본) — 글 한 편과 그 사진이 한 쪽에 담깁니다.
  한 쪽에 안 들어가면 사진을 조금씩 줄여 맞춰 보고, 그래도 넘치면 정해둔 쪽수(기본 2쪽)까지 씁니다.
  사진을 심하게 줄이느니 두 쪽을 쓰는 편이 낫다고 보고 **살짝 줄이기 → 쪽 늘리기 → 더 줄이기** 순으로 시도합니다.
  끝내 안 들어가는 글이 있으면 몇 편인지 알려 줍니다.
- **글마다 새 페이지** — 맞추려 하지 않고 그대로 흘립니다.
- **이어서 흐르게** — 글 사이에 구분선을 넣고 죽 이어 붙입니다. 쪽수가 가장 적습니다.

### 4. PDF로 저장, 또는 편집용 파일로 내보내기

`PDF로 저장 / 인쇄` 버튼을 누르고 인쇄 창에서:

| 항목 | 값 |
|---|---|
| 대상 | **PDF로 저장** |
| 여백 | **없음** |
| 배율 | **기본값(100%)** |
| 배경 그래픽 | **켬** |

사파리는 인쇄 창 왼쪽 아래 **PDF ▾ → PDF로 저장**을 쓰세요.

## 편집용 파일로 내보내기

PDF는 그대로 굳은 결과물입니다. 글자를 옮기거나 사진을 다시 앉히려면
미리보기 화면의 **편집용 파일로 내보내기**를 쓰세요.

| 형식 | 무엇을 할 수 있나 | 어디서 여나 |
|---|---|---|
| **Word (.docx)** | 글을 고쳐 쓰고, 스타일로 폰트·크기·여백을 한 번에 바꾸기 | 워드, 한글, 구글 문서, 페이지스 |
| **SVG** (쪽마다 한 장, .zip) | 글줄·사진 하나하나를 자유롭게 옮기고 키우기 | 일러스트레이터, 어피니티, 잉크스케이프, 피그마 |
| **HTML** | 사진까지 담긴 파일 하나로 보관하거나 다른 도구로 옮기기 | 아무 브라우저 |

### 인디자인에서 쓰려면

인디자인 네이티브 형식(IDML)은 만들지 않습니다.
대신 실무에서 원고를 넘기는 방식 그대로 쓰시면 됩니다.

- **원고 편집이 목적이면 `.docx`** — 인디자인 [파일 → 가져오기]로 배치하면
  단락 스타일(본문 / 장 제목 / 글 머리 / 사진 설명)이 그대로 따라옵니다.
- **판면을 그대로 옮기고 싶으면 `SVG`** — 배치는 되지만 글자는 고칠 수 없습니다.

### 형식별로 알아 둘 것

- **Word**는 흐름 문서라 쪽이 화면과 똑같이 떨어지지 않을 수 있습니다.
  글꼴이 컴퓨터마다 다르기 때문입니다. 판면을 그대로 보존해야 한다면 PDF나 SVG를 쓰세요.
- **SVG**에는 자동 줄바꿈이 없습니다. 그래서 화면에서 나뉜 줄을 **한 줄씩 따로** 담습니다.
  위치와 크기를 만지기에는 좋지만, 문장을 크게 고쳐 쓸 계획이라면 Word가 훨씬 편합니다.
- 사진은 **모두 파일 안에 담깁니다**. 따로 챙길 폴더가 없습니다.

## 중철 소책자 인쇄

`3단계 → 인쇄 방식 → 중철 소책자`를 고르면 A5 두 쪽을 A4 가로 한 장에,
**접어서 포개면 쪽 번호가 맞도록** 재배열해 출력합니다.

1. 양면 인쇄로 뽑습니다. (넘김 방향은 **짧은 쪽 넘김**부터 시도하고, 뒷면이 뒤집혀 나오면 반대로 바꾸세요.)
2. 전체를 반으로 접습니다.
3. 접힌 가운데를 스테이플러(중철기)로 두 군데 박으면 책이 됩니다.

쪽수는 자동으로 4의 배수가 되도록 빈 쪽을 채웁니다.

## 사진이 안 나올 때

불러오기 화면의 기록에 **`사진 N장 중 M장을 찾았습니다`** 가 나옵니다. 여기부터 보세요.

| 증상 | 원인과 해결 |
|---|---|
| `사진이 하나도 없습니다` | 내보내기를 요청할 때 미디어가 빠졌습니다. 페이스북에서 다시 요청하되 **미디어 화질을 중간 이상**으로 두세요. |
| `N장 중 0장을 찾았습니다` (JSON/HTML만 올린 경우) | 사진 파일은 ZIP 안에 있습니다. 압축을 풀거나 JSON만 골라 올리지 말고 **ZIP을 통째로** 올리세요. |
| `N장 중 일부만 찾았습니다` | 내보내기가 **여러 개의 ZIP으로 쪼개진** 경우입니다. `...-1.zip`, `...-2.zip`을 **한꺼번에 선택하거나 이어서** 올리면 나머지 사진이 붙습니다. |

페이스북은 사진을 게시물 파일에만 두지 않습니다. `posts/album/0.json`(앨범),
`your_uncategorized_photos.json`(앨범에 없는 사진)처럼 **따로 떨어진 파일**에 담는 경우가 많아서,
이 앱은 `posts/`·`photos_and_videos/` 폴더 아래의 JSON을 전부 열어 봅니다.
게시물에 이미 붙어 있는 사진이 앨범에도 있으면 **한 번만** 넣습니다.

## 알아 둘 것

**Graph API로 직접 읽기는 대부분 막혀 있습니다.**
개인 타임라인 글을 읽으려면 `user_posts` 권한과 앱 심사가 필요해서, 일반 토큰으로는 빈 목록이 돌아옵니다.
그래서 내보내기 ZIP이 기본 경로이고, 토큰 입력은 *실험적* 보조 기능으로만 넣어 두었습니다.
(본인 앱의 개발자/테스터 계정이거나 페이지 게시물이라면 동작할 수 있습니다.)

**한글 깨짐은 자동으로 고칩니다.**
페이스북 내보내기 JSON은 UTF-8 바이트를 `í` 처럼 이스케이프해 넣어 두기 때문에
그냥 읽으면 한글이 깨집니다. 이 앱은 문자열을 바이트로 되돌린 뒤 UTF-8로 다시 읽어 복구합니다.

**저장되지 않는 것**
`편집본 저장`으로 받는 JSON에는 글과 설정만 들어갑니다. 사진은 용량 때문에 빠지므로,
편집본을 다시 열 때 사진이 필요하면 **ZIP도 함께 올려 주세요.**

**동영상**은 책에 넣지 않습니다. 사진(JPG/PNG/GIF/WebP)만 사용합니다.

## 기술 메모

의존성이 없는 단일 HTML 파일입니다. 서버 없이 파일을 열어도 동작합니다.

- **ZIP 읽기** — 중앙 디렉터리만 먼저 읽고 필요한 항목만 그때그때 꺼내는 지연 방식이라,
  수 GB짜리 내보내기 파일도 통째로 메모리에 올리지 않습니다. ZIP64도 지원합니다.
  압축 해제는 브라우저 내장 `DecompressionStream('deflate-raw')`을 씁니다.
- **조판** — 브라우저의 페이지 나눔에 맡기지 않고 직접 배치합니다. 문단·사진을 최소 단위로 쪼개
  실제 높이를 재 가며 칼럼에 채우고, 페이지를 넘어가는 문단은 이진 탐색으로 잘라 이어 붙입니다.
  덕분에 **정확한 쪽 번호와 목차 쪽수**를 만들 수 있습니다. (목차 분량이 본문 쪽수를 바꾸므로
  값이 안정될 때까지 되풀이해 계산합니다.)
- **인쇄** — `@page { margin: 0 }` + 쪽마다 정확한 mm 크기의 `.page` 요소.
  화면에서 보이는 것이 그대로 출력됩니다.
- **내보내기** — ZIP 쓰기(CRC32 + `CompressionStream`)를 직접 구현해 `.docx`와 SVG 묶음을 만듭니다.
  Word는 OOXML을 손으로 조립하며, `w:pPr` 자식 요소 순서까지 스키마에 맞춥니다.
  SVG는 조판된 화면에서 `Range`로 **글줄의 실제 위치**를 이진 탐색으로 읽어 옮깁니다.

성능 참고 (Chromium, 게시물 2,000개 · 59만 자):
이어서 흐르게 **1,435쪽 / 9초**, 글 하나를 한 쪽에 **2,200쪽 / 10초**.

### 브라우저

Chrome/Edge 103+, Safari 16.4+, Firefox 113+ 에서 동작합니다.
(`DecompressionStream`이 필요합니다. 미리보기 확대는 `zoom`을 사용합니다.)

### 테스트

실제 내보내기와 같은 구조(한글이 깨진 채로 들어 있는 JSON + 사진)의 샘플 ZIP을 만들어
헤드리스 브라우저로 돌립니다.

```sh
python3 tests/make_sample_export.py tests/sample_export.zip
npm install playwright
node tests/run.mjs
```

한글 복구, 사진 추출(앨범·미분류·빠진 사진 포함), 다섯 가지 판형에서의 넘침 여부,
글 하나가 한 쪽을 차지하는지, 목차 쪽수 정확도, 소책자 배치 순서,
그리고 내보낸 .docx·SVG·HTML의 구조와 XML 적합성까지 확인합니다.
